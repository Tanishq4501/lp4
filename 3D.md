# PS 3D: Fault detection in NASA turbofan sensor data with an LSTM autoencoder

> Notebook: `3D.ipynb` | Template: C (windowed LSTM autoencoder) | Wider theory: [Viva_Theory.md](Viva_Theory.md) sections 1 and 4

## 1. What the PS asks (in plain words)
Detect faults in NASA turbofan engine sensor data with an LSTM autoencoder: pre-process (drop useless columns, smooth, scale, window per engine), train on healthy windows, flag faulty windows.

## 2. Dataset
- `nasa.csv`: **20,631 rows**, 100 engines run until failure. Columns: `unit` (engine), `cycle`, 3 settings, `sensor1`-`sensor21`, `RUL` (remaining useful life) and `Fault_Label` (1 when `RUL <= 30`, the last 30 cycles).
- Informative sensors: **15** (the constant sensors are dropped). Engines 1-80 train, engines 81-100 test.
- Your windows: 30 cycles. Healthy training windows 11,338; test windows 3,913, of which **620 are faulty**.

## 3. Notebook walkthrough: every cell, and why

### Cell 0: imports
```python
import tensorflow as tf
from tensorflow import keras
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler, MinMaxScaler
from sklearn.metrics import classification_report, confusion_matrix, roc_auc_score
```
**Why:** `tensorflow` first (DLL safety). `MinMaxScaler` scales the features, `classification_report`, `confusion_matrix`, `roc_auc_score` evaluate the detector, `matplotlib` plots.

### Cell 1: dataset
```python
#dataset
layers = tf.keras.layers
keras.utils.set_random_seed(42)
df = pd.read_csv("nasa.csv")
df.head()
```
**Why:** `layers = tf.keras.layers` and `set_random_seed(42)` sit in the dataset cell: a short name for the layers and repeatable training. `df.head()` shows the columns, with `RUL` and `Fault_Label` at the end.

### Cell 2: sort by engine and cycle
```python
df = df.sort_values(["unit", "cycle"]).reset_index(drop=True)
```
**Why:** Sorting by `unit` then `cycle` puts each engine's life in time order, which windowing needs.

**Why not the alternative:** Not leaving the order to chance.

### Cell 3: choose sensors and smooth
```python
sensors = [c for c in df.columns if c.startswith("sensor") and df[c].nunique() > 1]   # keep informative sensors only (RUL would leak the answer)
N_FEATURES = len(sensors)
data = df.copy()
data[sensors] = data.groupby("unit")[sensors].transform(lambda s: s.rolling(10, min_periods=1).mean())   # smooth each engine
```
**Why:** `sensors` keeps only `sensor*` columns that actually vary (`nunique() > 1`): constant sensors carry no information and break scaling. **`unit`, `cycle` and `RUL` are not inputs**: the fault label is defined from `RUL`, so using it would leak the answer. `data = df.copy()` then a **rolling mean of 10 per engine** (`groupby("unit")`) smooths the noise; copying first means re-running the cell never smooths twice.

**Why not the alternative:** Not RUL as an input (target leakage). Not smoothing across engines (it would mix two engines). Not skipping smoothing: in my test AUC dropped from 0.92 to about 0.67.

### Cell 4: split by engine and scale
```python
#split
train_rows, test_rows = data[data.unit <= 80], data[data.unit > 80]       # split by engine, not by row
scaler = MinMaxScaler().fit(train_rows.loc[train_rows.Fault_Label == 0, sensors])
```
**Why:** Engines 1-80 for training and 81-100 for testing: an engine is an independent unit. `MinMaxScaler` is fitted on the **healthy training rows** only.

**Why not the alternative:** Not a random row split: overlapping windows from the same engine would appear in both train and test (leakage).

### Cell 5: window (the extra step)
```python
#window <- extra thing
def make_windows(rows):                                                   # windows inside each engine, label = last step
    X, y = [], []
    for u, g in rows.groupby("unit"):
        a, l = scaler.transform(g[sensors]), g["Fault_Label"].values
        for i in range(len(g) - 30 + 1):
            X.append(a[i:i + 30]); y.append(l[i + 30 - 1])
    return np.array(X, dtype="float32"), np.array(y)
Wtrall, ytr = make_windows(train_rows)
Xtes, yte = make_windows(test_rows)
Xtrn = Wtrall[ytr == 0]                                                   # healthy windows only

print(Xtrn.shape, Xtes.shape, yte.sum(),len(yte))
```
**Why:** `make_windows` loops **inside each engine** (`groupby("unit")`) and slides a window of 30 cycles; the window label is the label of its **last** cycle. Windows never cross two engines. `Xtrn` keeps only healthy training windows. Result: `(11338, 30, 15) (3913, 30, 15) 620 3913`.

**Why not the alternative:** Not windows across engine boundaries (the end of one engine and the start of the next make no sense together). Not the 'any step' rule here: the last step tells whether the engine is in its final 30 cycles.

### Cell 6: define the LSTM autoencoder
```python
#layers
inp = keras.Input(shape=(30,N_FEATURES))
x = layers.LSTM(32)(inp)
x = layers.RepeatVector(30)(x)
x = layers.LSTM(32,return_sequences=True)(x)
out = layers.TimeDistributed(layers.Dense(N_FEATURES))(x)
ae = keras.Model(inp,out)
ae.summary()
```
**Why:** `LSTM(32)` -> `RepeatVector(30)` -> `LSTM(32, return_sequences=True)` -> `TimeDistributed(Dense(15))`, with `N_FEATURES` = 15 sensors.

**Why not the alternative:** Not a Dense autoencoder: it ignores the order of cycles.

### Cell 7: compile and train with early stopping
```python
ae.compile(optimizer="adam",loss="mse",metrics=["mae"])
stop = keras.callbacks.EarlyStopping(monitor="val_loss",patience=4,restore_best_weights=True)
hist = ae.fit(Xtrn,Xtrn,epochs=20,batch_size=128,validation_split=0.1,callbacks=[stop])
```
**Why:** MSE, input = target, `EarlyStopping(patience=4, restore_best_weights=True)`, 20 epochs maximum, batch 128, `validation_split=0.1`.

**Why not the alternative:** Not a fixed long run.

### Cell 8: reconstruction error and threshold
```python
#reconstruction error
err_train = np.mean((Xtrn - ae.predict(Xtrn))**2,axis=(1,2))
err_test = np.mean((Xtes - ae.predict(Xtes))**2,axis=(1,2))
threshold = np.percentile(err_train,99)
pred = (err_test > threshold).astype(int)
print(threshold, pred.sum(),len(pred))
```
**Why:** Error per window with `axis=(1,2)`. Threshold = **99th percentile** of the healthy training errors: a strict rule that gives high precision (few false alarms).

**Why not the alternative:** Not the 95th percentile: it would catch more faults (higher recall) but raise false alarms. The choice is a trade-off to state.

### Cell 9: evaluate
```python
#evaluate
print(classification_report(yte,pred,target_names=["normal","anomaly"],digits=3))
print(confusion_matrix(yte,pred))
print(round(roc_auc_score(yte,err_test),4))
```
**Why:** Anomaly row (precision, recall, F1), confusion matrix and ROC-AUC. AUC measures separation without the threshold; the strict 99th percentile explains why recall is only 0.46.

**Why not the alternative:** Not accuracy (0.905): healthy windows dominate.

### Cell 10: error histogram and training curve
```python
#plot
for k in (0,1):
    plt.hist(err_test[yte==k],50,range=(0,np.percentile(err_test,99)),alpha=0.6,label=["normal","anomaly"][k])
plt.axvline(threshold,color="k",ls="--",label="threshold")
plt.legend()
pd.DataFrame(hist.history).plot();
plt.show()
```
**Why:** Shows the overlap of healthy and faulty errors with the threshold line, and the loss curves.

**Why not the alternative:** Not only numbers.

### Cell 11: one example
```python
#one example
i = np.where(yte == 0)[0][0]                       # first healthy window
j = np.where((yte == 1) & (pred == 1))[0][0]       # first faulty window the model caught
for n, k in enumerate((i, j)):
```

**Why not the alternative:** Not only scores.

### Cell 12: error over time for one engine
```python
#error over time for one engine
g = test_rows[test_rows.unit == 81]; n = len(g) - 30 + 1                  # first test engine = first n windows
cyc, e81 = g["cycle"].values[29:], err_test[:n]
plt.plot(cyc, e81); plt.axhline(threshold, color="k", ls="--")            # error per cycle vs threshold

```
**Why:** For the first test engine (81) it plots the error per cycle with the threshold line and the true fault windows in orange. The error stays low for about 200 cycles and then rises steeply, crossing the threshold shortly after the true fault window begins: the model flags the fault slightly late. `g["cycle"].values[29:]` aligns one point per window (the first 29 cycles have no window).

**Why not the alternative:** Not only aggregate scores: the engine's life shows when the model reacts.

## 4. Terminology used in this notebook

| Term | Meaning |
|---|---|
| **Window** | W consecutive rows treated as one sample, giving data of shape (samples, W, features). |
| **LSTM** | A recurrent layer with a memory cell and gates (input, forget, output); it learns dependencies over time and avoids the vanishing gradient of plain RNNs. |
| **RepeatVector** | Copies the encoded vector once per time step so the decoder LSTM has a sequence to unroll. |
| **TimeDistributed** | Applies the same Dense layer to every time step of a sequence. |
| **EarlyStopping** | Stops training when the validation loss stops improving (and, with `restore_best_weights`, goes back to the best epoch). |
| **Autoencoder** | A network trained to reproduce its input through a narrow middle layer (`fit(X, X)`), so it learns a compressed representation. |
| **Bottleneck (latent code)** | The narrow middle layer. It must be smaller than the input, otherwise the network just copies. |
| **Reconstruction error** | How far the rebuilt sample is from the original (mean squared difference per sample). Large for anomalies. |
| **Threshold** | The error value above which a sample is called an anomaly. |
| **Percentile** | The value below which a given percentage of the data lies (95th percentile = larger than 95 % of normal errors). |
| **Anomaly** | A sample that does not look like normal data (fraud, abnormal heartbeat, faulty engine, unseen letter). |
| **MinMaxScaler** | Scales each feature to 0..1 using the training minimum and maximum. |
| **Data leakage** | Information from test data (or from the answer) leaking into training, for example fitting a scaler on all data or keeping RUL as an input. |
| **Precision** | Of everything flagged positive, the fraction that really is positive: TP / (TP + FP). |
| **Recall** | Of all real positives, the fraction found: TP / (TP + FN). |
| **F1 score** | Harmonic mean of precision and recall: 2PR / (P + R). |
| **ROC-AUC** | Probability that a random anomaly gets a higher score than a random normal sample. 0.5 = guessing, 1.0 = perfect. Needs no threshold. |
| **RUL** | Remaining useful life: cycles left before the engine fails. `Fault_Label` is 1 when it is 30 or less. |
| **Rolling mean** | Average of the last 10 readings; smooths noise. |
| **Turbofan engine** | A jet engine; each engine in the file runs from healthy to failure. |

## 5. Theory you must be able to explain

**Same idea as 3C with more preprocessing.** Windows of sensor readings feed an LSTM autoencoder trained on healthy windows; faulty windows are rebuilt badly.

**Why `RUL` is dropped.** The fault label is defined as `RUL <= 30`; giving the model `RUL` would hand it the answer (target leakage).

**Why smoothing matters.** Raw sensors are noisy; averaging 10 readings per engine reveals the slow degradation trend, lifting AUC from about 0.67 to 0.92 in my test.

**Why split by engine and window inside each engine.** Windows overlap, so a random row split would put neighbouring windows in train and test. Engines are independent, and a window across two engines would be meaningless.

**Why the 99th percentile.** A strict threshold keeps false alarms low (precision 0.885) but misses more than half of the faulty windows (recall 0.458): the faults near the start of the last 30 cycles look almost healthy. Use a lower percentile to catch more.

**Engine plot.** The error grows as the engine nears failure and crosses the threshold late: the model reacts when degradation becomes clear.

## 6. Why we did this, and why not that

| Decision | Why we did it | Why not the alternative |
|---|---|---|
| Drop `RUL`, `unit`, `cycle` | RUL defines the label (leakage); unit and cycle are identifiers | Using RUL gives a fake perfect result |
| Keep sensors with `nunique() > 1` | Constant sensors carry no information | Scaling a constant column divides by zero |
| Rolling mean of 10 per engine | Reduces noise: AUC about 0.67 -> 0.92 | No smoothing, or smoothing across engines |
| Split by engine (1-80 / 81-100) | No leakage between overlapping windows | Random row split |
| Windows inside each engine, label of last step | Windows never mix engines | One long window loop over all rows |
| 99th percentile threshold | High precision, few false alarms | 95th percentile gives more false alarms |
| `data = df.copy()` | Re-running the cell does not smooth twice | Smoothing `df` in place |
