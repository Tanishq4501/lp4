## 1. What the PS asks (in plain words)
Classify hand-sign letters with an FNN (SGD or Adam): load the data, define the architecture, train, evaluate, plot.

## 2. Dataset
- Sign-Language MNIST: 27,455 training and 7,172 test images, 28x28 grey, hand signs for letters.
- Labels run **0-24 with 9 missing** (J and Z need motion), so there are 24 classes but labels go up to 24: the output layer needs **25** units.
- Files: `sign_mnist_train.csv`, `sign_mnist_test.csv` (your notebook reads them from the `sg/` folder).

## 3. Notebook walkthrough: every cell, and why

### Cell 0: imports
```python
import tensorflow as tf
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.metrics import classification_report
```
**Why:** `tensorflow` is imported first (on this machine importing numpy or pandas before TensorFlow can crash the TensorFlow DLL). `classification_report` gives precision, recall and F1 per class; `matplotlib` draws the curves and the example image.

### Cell 1: alias for the layers module
```python
L = tf.keras.layers
```
**Why:** `L = tf.keras.layers` is only a short name so each layer is written `L.Dense(...)` instead of `tf.keras.layers.Dense(...)`.

### Cell 2: load the data
```python
tr = pd.read_csv("sg/sign_mnist_train.csv")
te = pd.read_csv("sg/sign_mnist_test.csv")
Xtr,ytr = tr.drop(columns="label").values.reshape(-1,28,28,1) / 255, tr.label.values
Xte,yte = te.drop(columns="label").values.reshape(-1,28,28,1) / 255, te.label.values
```
**Why:** Same CSV layout as MNIST (`label` first, then 784 pixels). The files are read from the `sg/` folder next to the notebook.

**Why not the alternative:** Not `to_categorical` (one-hot labels): the sparse loss accepts the integer labels directly, so no conversion is needed. Not skipping `/ 255`: unscaled pixels (0-255) make training slow and unstable.

### Cell 3: define the model (FNN, 25 outputs)
```python
model = tf.keras.Sequential([L.Flatten(), L.Dense(256, activation="relu"), L.Dense(128, activation="relu"), L.Dense(25, activation="softmax")])
model.summary()
```
**Why:** `Flatten` turns the image into one long vector; two `Dense` layers with ReLU (256 then 128 units) learn combinations of pixels; the last `Dense` has one unit per class with `softmax`, so the outputs are probabilities that sum to 1. **The last layer is `Dense(25)`**: the biggest label is 24, so the output needs `max label + 1 = 25` units even though label 9 never occurs.

**Why not the alternative:** Not more or bigger layers: this size is enough to show the effect and trains in seconds. Not `sigmoid` or no activation at the end: softmax is the right output for exactly one correct class among several. Not `Dense(24)`: label 24 would be out of range; not `Dense(10)` (copied from 1A): you get "label value 24 is outside the valid range [0, 10)".

### Cell 4: compile and train
```python
model.compile(optimizer="adam", loss="sparse_categorical_crossentropy", metrics=["accuracy"])
h = model.fit(Xtr, ytr, epochs=12, batch_size=128, validation_data=(Xte, yte))
```
**Why:** `adam` (the PS allows SGD or Adam), sparse categorical cross-entropy, 12 epochs, batch 128, test data as validation (215 iterations per epoch).

**Why not the alternative:** Not more epochs: validation loss is lowest at epoch 8 and then rises while training accuracy goes to 99 %, so the model is already over-fitting.

### Cell 5: evaluate
```python
print(model.evaluate(Xte, yte))                                  
print(classification_report(yte, model.predict(Xte).argmax(1)))
```
**Why:** `model.evaluate` returns `[test loss, test accuracy]`. `model.predict(Xte)` gives one probability per class and `.argmax(1)` picks the most probable class; `classification_report` then shows precision, recall and F1 per class so you can see which classes are weak.

**Why not the alternative:** Not accuracy alone: it hides which classes fail (letters R, U, V, S and T are the weakest).

### Cell 6: training curves
```python
pd.DataFrame(h.history).plot(); 
plt.show()
```
**Why:** `pd.DataFrame(h.history).plot()` draws loss and accuracy for training and validation in one line. Both curves falling together is healthy; training much better than validation means over-fitting.

**Why not the alternative:** Not a separate plot call for each curve: the DataFrame draws all four lines at once.

### Cell 7: one example
```python
#one example
names = [chr(65+k) for k in range(25)]                         # label 0 = A ... 24 = Y
i = 0                                                          # any test image
p = model.predict(Xte[i:i+1])[0]                               # one probability per class
plt.imshow(Xte[i].squeeze(), cmap="gray"); plt.title(f"true {names[yte[i]]} | predicted {names[p.argmax()]} ({p.max():.0%})")
plt.show()
```
**Why:** Shows what a single prediction looks like: the model returns one probability per class, `argmax` gives the label and the title shows the confidence. It makes the idea concrete in the viva (an image goes in, probabilities come out).

**Why not the alternative:** Not only the aggregate accuracy: one visible example is easier to explain. 

## 4. Terminology used in this notebook

| Term | Meaning |
|---|---|
| **Adam** | An optimiser that keeps running averages of the gradient and its square, so every weight gets its own adaptive step. Default learning rate 1e-3. |
| **Over-fitting** | The model memorises the training data and does worse on new data: training score keeps rising, validation score stalls. |
| **Sparse categorical cross-entropy** | Multi-class loss `-log(probability of the true class)` that takes integer labels (7) instead of one-hot vectors. |
| **Softmax** | Output activation that turns scores into probabilities that sum to 1 (one per class). |
| **Dense layer** | A fully connected layer: every input connects to every unit. Parameters = `inputs * units + units`. |
| **Flatten** | Turns a 2-D or 3-D feature map into one long vector so Dense layers can use it. |
| **Normalisation (/255)** | Dividing pixels by 255 so inputs are in 0..1: small, similar-sized inputs give stable, faster training. |
| **Accuracy** | Correct predictions divided by all predictions. Misleading when classes are imbalanced. |
| **Precision** | Of everything flagged positive, the fraction that really is positive: TP / (TP + FP). |
| **Recall** | Of all real positives, the fraction found: TP / (TP + FN). |
| **F1 score** | Harmonic mean of precision and recall: 2PR / (P + R). |
| **Support** | How many true samples of each class are in the test data. |

## 5. Theory you must be able to explain

**Output size rule.** The last layer needs `max label + 1` units. `print(ytr.max())` shows 24, so 25 units. Using 10 (copied from MNIST) crashes with "label value 24 is outside the valid range".

**Over-fitting.** Training accuracy rises to 99.3 % while validation accuracy stays around 72 % and validation loss rises after epoch 8 (0.93 to 1.08). The gap between the curves is the sign. Fixes: Dropout, fewer epochs, `EarlyStopping`, data augmentation.

**Why the test score is lower than the training score.** The test images differ from the training ones, and an FNN with 235k parameters can memorise the training set.

**Why the report has 24 rows.** The classification report lists only labels that occur: label 9 is absent.

## 6. Why we did this, and why not that

| Decision | Why we did it | Why not the alternative |
|---|---|---|
| `Dense(25)` output | Labels go up to 24 | Not `Dense(10)` (MNIST value) and not `Dense(24)` |
| Adam | Faster convergence | SGD would need many more epochs |
| 12 epochs | Enough to learn; validation peaks around epochs 8-11 | More would only increase over-fitting |
| No regularisation | Kept the baseline simple | Dropout or early stopping would reduce the gap |
| Read from `sg/` | Keeps the files separate from the other datasets | No technical reason; only the path changes |
