## 3. Notebook walkthrough: every cell, and why

### Cell 0: imports
```python
import tensorflow as tf
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.metrics import classification_report
from sklearn.model_selection import train_test_split
```
**Why:** `tensorflow` is imported first (on this machine importing numpy or pandas before TensorFlow can crash the TensorFlow DLL). `classification_report` gives precision, recall and F1 per class; `matplotlib` draws the curves and the example image. `train_test_split` is needed here because the CIFAR CSV has no separate test file.

### Cell 1: alias for the layers module
```python
L = tf.keras.layers
```
**Why:** `L = tf.keras.layers` is only a short name so each layer is written `L.Dense(...)` instead of `tf.keras.layers.Dense(...)`.

### Cell 2: read the CIFAR CSV
```python
df = pd.read_csv("cifar-10.csv",dtype=np.uint8)
df.head()
```
**Why:** Reads the CSV as `uint8` to save memory; the label is the last column.

**Why not the alternative:** Not reading as the default int64: `dtype=np.uint8` keeps the 50,000 x 3,073 table small in memory.

### Cell 3: reshape to images, scale, split 80/20
```python
X = df.drop(columns="label").values.reshape(-1,3,32,32).transpose(0,2,3,1).astype("float32") / 255
Xtr,Xte,ytr,yte = train_test_split(X,df.label.values.astype(int),test_size=0.2,random_state=42)
```
**Why:** Same as 1C: `(3,32,32)` planes -> `transpose(0,2,3,1)` -> `(32,32,3)` images, `/ 255`, 80/20 split with `random_state=42`.

**Why not the alternative:** Not `reshape(-1,32,32,3)` directly: the pixels are stored as three colour planes (all R, then all G, then all B), so a direct reshape would scramble the colours. Not skipping the split: there is no test file, so we make one.

### Cell 4: define the model (CNN)
```python
model = tf.keras.Sequential([L.Conv2D(32, 3, activation="relu"), L.MaxPooling2D(), L.Conv2D(64, 3, activation="relu"), L.MaxPooling2D(),L.Flatten(), L.Dense(128, activation="relu"), L.Dense(10, activation="softmax")])
model.summary()
```
**Why:** Two `Conv2D` layers (32 then 64 filters of 3x3, ReLU) find local patterns; each `MaxPooling2D` halves the size; `Flatten` + `Dense(128)` combines the patterns; the last `Dense` with `softmax` gives class probabilities. Shapes: 32x32x3 -> `Conv2D(32,3)` 30x30x32 -> pool 15x15x32 -> `Conv2D(64,3)` 13x13x64 -> pool 6x6x64 -> Flatten 2,304 -> Dense 128 -> Dense 10. Parameters: 896 + 18,496 + 295,040 + 1,290 = **315,722**.

**Why not the alternative:** Not an FNN: it ignores where pixels are and has far more parameters for images. Not `padding="same"` or more layers: the simple version already works and is easy to explain and count.

### Cell 5: compile and train
```python
model.compile(optimizer="adam", loss="sparse_categorical_crossentropy", metrics=["accuracy"])
h = model.fit(Xtr, ytr, epochs=10, batch_size=128, validation_data=(Xte, yte))
```
**Why:** Adam, sparse categorical cross-entropy, 10 epochs, batch 128 (313 iterations per epoch on 40,000 images), test data as validation.

**Why not the alternative:** Not SGD: slower. Not many more epochs: training accuracy (77 %) already pulls ahead of validation (70 %), a sign of mild over-fitting.

### Cell 6: evaluate
```python
print(model.evaluate(Xte, yte))                                  
print(classification_report(yte, model.predict(Xte).argmax(1)))
```
**Why:** `model.evaluate` returns `[test loss, test accuracy]`. `model.predict(Xte)` gives one probability per class and `.argmax(1)` picks the most probable class; `classification_report` then shows precision, recall and F1 per class so you can see which classes are weak.

**Why not the alternative:** Not accuracy alone: it hides which classes fail (cat, bird and dog are the weakest).

### Cell 7: training curves
```python
pd.DataFrame(h.history).plot(); 
plt.show()
```
**Why:** `pd.DataFrame(h.history).plot()` draws loss and accuracy for training and validation in one line. Both curves falling together is healthy; training much better than validation means over-fitting.

**Why not the alternative:** Not a separate plot call for each curve: the DataFrame draws all four lines at once.

### Cell 8: one example
```python
#one example
names = ["airplane","automobile","bird","cat","deer","dog","frog","horse","ship","truck"]
i = 0                                                          # any test image
p = model.predict(Xte[i:i+1])[0]                               # one probability per class
plt.imshow(Xte[i].squeeze(), cmap="gray"); plt.title(f"true {names[yte[i]]} | predicted {names[p.argmax()]} ({p.max():.0%})")
plt.show()
```
**Why:** Shows what a single prediction looks like: the model returns one probability per class, `argmax` gives the label and the title shows the confidence. It makes the idea concrete in the viva (an image goes in, probabilities come out).

**Why not the alternative:** Not only the aggregate accuracy: one visible example is easier to explain. The example may be wrong: the CNN is only 70 % accurate.

## 4. Terminology used in this notebook

| Term | Meaning |
|---|---|
| **Conv2D** | A layer of small filters (for example 3x3) that slide over an image and detect local patterns. |
| **Filter / kernel** | The small weight window of a convolution layer. `Conv2D(32, 3)` learns 32 filters of size 3x3. |
| **Feature map** | The output of one filter: where its pattern was found in the input. |
| **Padding** | `valid` = no padding (output shrinks); `same` = zero-pad so the size is kept at stride 1. |
| **Stride** | How many positions the filter jumps each step; stride 2 halves the size. |
| **MaxPooling** | Keeps the maximum of each block (2x2): halves width and height, reduces computation, adds small shift invariance. |
| **Flatten** | Turns a 2-D or 3-D feature map into one long vector so Dense layers can use it. |
| **Dense layer** | A fully connected layer: every input connects to every unit. Parameters = `inputs * units + units`. |
| **ReLU** | `max(0, x)`. Cheap hidden-layer activation that does not saturate for positive values. |
| **Softmax** | Output activation that turns scores into probabilities that sum to 1 (one per class). |
| **Adam** | An optimiser that keeps running averages of the gradient and its square, so every weight gets its own adaptive step. Default learning rate 1e-3. |
| **Over-fitting** | The model memorises the training data and does worse on new data: training score keeps rising, validation score stalls. |
| **Accuracy** | Correct predictions divided by all predictions. Misleading when classes are imbalanced. |
| **Precision** | Of everything flagged positive, the fraction that really is positive: TP / (TP + FP). |
| **Recall** | Of all real positives, the fraction found: TP / (TP + FN). |
| **F1 score** | Harmonic mean of precision and recall: 2PR / (P + R). |

## 5. Theory you must be able to explain

**What a convolution does.** A 3x3 filter slides over the image computing a weighted sum; the result is a feature map showing where the pattern occurs. Early layers find edges, later layers combine them into shapes. The same filter weights are reused everywhere (weight sharing), so a CNN needs far fewer parameters per feature than an FNN.

**Pooling.** `MaxPooling2D` keeps the largest value in each 2x2 block, halving width and height, reducing computation and giving small shift invariance.

**Shape and parameter formulas (no padding).** Output = `(n - k)/stride + 1`; conv parameters = `(k*k*channels_in + 1) * filters`. Layer 1: (3*3*3+1)*32 = 896; layer 2: (3*3*32+1)*64 = 18,496.

**Why the CNN beats the FNN here.** Same data, same optimiser: 69.7 % against 46.7 %, because the CNN uses local patterns, weight sharing and translation invariance.

**Mild over-fitting.** Training accuracy 77 % against validation 70 %. Dropout, data augmentation or a smaller dense layer would narrow the gap.

## 6. Why we did this, and why not that

| Decision | Why we did it | Why not the alternative |
|---|---|---|
| Two conv + two pooling blocks | Learn patterns and shrink the maps step by step | Not an FNN (47 %) |
| 32 then 64 filters | More filters deeper: simple edges first, richer shapes later | Not more layers: this size is enough for a clear comparison with 1C |
| No `padding="same"` | Simplest default; sizes are easy to compute (30, 15, 13, 6) | `same` keeps sizes but changes nothing important here |
| `Flatten` + `Dense(128)` | Combine the learned patterns before classifying | Global average pooling would also work but is not needed |
| Adam, 10 epochs | Fast convergence; validation stops improving near the end | More epochs increase the train/validation gap |

## 9. Viva questions with answers

**Q. What does a convolutional layer do?**

A. It slides small filters over the image and detects local patterns, producing feature maps.

**Q. Why pooling?**

A. It halves the size, reduces computation and gives small shift invariance.

**Q. Output size of Conv2D(32,3) on 32x32 without padding?**

A. 30x30x32 (`(32-3)/1 + 1`).

**Q. Parameters of your first conv layer?**

A. (3x3x3+1)x32 = 896.

**Q. Why is the CNN better than the FNN?**

A. Local connectivity, weight sharing and spatial structure: 69.7 % against 46.7 %.

**Q. Is it over-fitting?**

A. Mildly: train 77 % against validation 70 %; Dropout or augmentation would help.

**Q. Why is cat hard?**

A. Cats look like dogs and other small animals at 32x32.
