## 1. What the PS asks (in plain words)
Detect fraudulent credit-card transactions with an autoencoder: train it on normal transactions only, flag transactions it cannot rebuild, and evaluate the detector.

## 2. Dataset
- `creditcard.csv`: 284,807 transactions, only **492 frauds (0.17 %)**. Columns: `Time`, `V1`-`V28` (already PCA components), `Amount`, and `Class` (1 = fraud).
- Your split: 80/20 stratified; training uses only the **227,451 normal** training rows; the test set has 56,962 rows including **98 frauds**.

## 3. Notebook walkthrough: every cell, and why

### Cell 0: imports
```python
import tensorflow as tf
from tensorflow import keras
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.metrics import classification_report, roc_auc_score, confusion_matrix
```
**Why:** `tensorflow` first (DLL safety on this machine). `train_test_split` splits the data, `StandardScaler` / `MinMaxScaler` scale features, `classification_report`, `confusion_matrix` and `roc_auc_score` evaluate the detector (never plain accuracy), `matplotlib` draws the histogram and curves.

### Cell 1: dataset
```python
#dataset
layers = tf.keras.layers
df = pd.read_csv("creditcard.csv")
df.head()
```
**Why:** Loads the table; `df.head()` shows `Class` as the last column (0 normal, 1 fraud). No random seed is set in this notebook, so the AUC varies a little between runs (about 0.93-0.96).

### Cell 2: split and scale
```python
#split and scaling
X,y = df.drop(columns="Class").values.astype("float32"), df["Class"].values
Xtr,Xte,ytr,yte = train_test_split(X,y,test_size=0.2,stratify=y,random_state=42)
scaler = StandardScaler().fit(Xtr[ytr==0])
Xtrn = scaler.transform(Xtr[ytr==0]) # normal only
Xtes = scaler.transform(Xte) # normal + fraud
print(Xtrn.shape, yte.sum(), len(yte))
```
**Why:** `X` is all columns except `Class`; `y` is `Class`. `stratify=y` keeps the same 0.17 % fraud rate in train and test (essential with so few frauds). **The scaler is fitted on normal training rows only** and applied to the test set (normal + fraud). `Xtrn` is the normal training data the autoencoder will learn from. `StandardScaler` (mean 0, std 1) is used because the features are standardised-style PCA components with no fixed range.

**Why not the alternative:** Not fitting the scaler on all data (leakage and fraud would shape the scale). Not training on fraud rows: the autoencoder must learn only what normal looks like. Not MinMaxScaler: the output layer is linear, and standardised values can be negative.

### Cell 3: define the autoencoder
```python
#layers
inp = keras.Input(shape=(30,))
x = layers.Dense(24,activation="relu")(inp)
x = layers.Dense(14,activation="relu")(x)
z = layers.Dense(7,activation="relu")(x)
x = layers.Dense(14,activation="relu")(z)
x = layers.Dense(24,activation="relu")(x)
out = layers.Dense(30,activation="linear")(x)
ae = keras.Model(inp,out)

ae.summary()
```
**Why:** Encoder 30 -> 24 -> 14 -> **7 (bottleneck)**, decoder 7 -> 14 -> 24 -> 30. The **output layer is linear** because standardised data can be negative or large. 2,421 parameters. The bottleneck (7) is much smaller than the input (30), so the network must compress.

**Why not the alternative:** Not a bottleneck of 30 (it would copy fraud perfectly). Not a `sigmoid` output: that only produces 0..1 and cannot rebuild negative standardised values.

### Cell 4: compile and train
```python
#compile
ae.compile(optimizer="adam",loss="mse",metrics=["mae"])
hist = ae.fit(Xtrn,Xtrn,epochs=20,batch_size=256,validation_split=0.1)
```
**Why:** `loss="mse"` is the reconstruction error. `ae.fit(Xtrn, Xtrn)` uses the input as the target (unsupervised). 20 epochs, batch 256, `validation_split=0.1` watches the loss on held-out normal data. `mae` is only an extra metric.

**Why not the alternative:** Not labels as targets (no supervision). Not training with fraud included: it would learn to rebuild fraud too.

### Cell 5: reconstruction error and threshold
```python
#reconstruction error
err_train = np.mean((Xtrn - ae.predict(Xtrn))**2,axis=1)
err_test = np.mean((Xtes - ae.predict(Xtes))**2,axis=1)
threshold = err_train.mean() + 3 * err_train.std()
pred = (err_test > threshold).astype(int)
print(threshold, pred.sum(),len(pred))
```
**Why:** For every transaction the mean squared difference between input and rebuilt output is the **reconstruction error** (`axis=1`, 2-D data). The threshold is `mean + 3 x std` of the **training (normal) errors**: fraud is very rare, so a strict rule keeps false alarms low. `pred = 1` (fraud) when the error is above it.

**Why not the alternative:** Not the 95th percentile here: it flags 5 % of normal transactions (in my test about 3,000 alarms with precision 0.03). Not a threshold picked on test labels (that would be cheating).

### Cell 6: evaluate
```python
#evaluate
print(classification_report(yte,pred,target_names=["normal","anomaly"],digits=3))
print(confusion_matrix(yte,pred))
print(round(roc_auc_score(yte,err_test),4))
```
**Why:** The detector's job is to flag the anomaly class, so the report is read on the **anomaly row** (precision, recall, F1); the confusion matrix `[[TN, FP], [FN, TP]]` shows the counts; **ROC-AUC** scores the error itself without choosing a threshold (0.5 = guessing, 1.0 = perfect).

**Why not the alternative:** Not accuracy: 99.83 % of transactions are normal, so 'always normal' scores 99.8 % accuracy and finds no fraud.

### Cell 7: error histogram and training curve
```python
#plot
for k in (0,1):
    plt.hist(err_test[yte==k],50,range=(0,np.percentile(err_test,99)),alpha=0.6,label=["normal","anomaly"][k])
plt.axvline(threshold,color="k",ls="--",label="threshold")
plt.legend()
pd.DataFrame(hist.history).plot();
plt.show()
```
**Why:** The histogram of reconstruction errors (normal against anomaly) with the dashed threshold line is the key plot: the less the two colours overlap, the better the detector. The training curve shows the loss falling and flattening (`validation_split` here is a slice of the normal training data).

**Why not the alternative:** Not only numbers: the overlap in the histogram explains the precision and recall values.

### Cell 8: one example
```python
#one example
i = np.where(yte == 0)[0][0]                       # first normal transaction
j = np.where((yte == 1) & (pred == 1))[0][0]       # first fraud the model caught
print(f"normal: error {err_test[i]:.3f} -> {'FRAUD' if pred[i] else 'ok'}")
print(f"fraud : error {err_test[j]:.3f} -> {'FRAUD' if pred[j] else 'ok'} | threshold {threshold:.3f}")
plt.plot(Xtes[j], label="input"); plt.plot(ae.predict(Xtes[j:j+1])[0], label="reconstruction")
plt.legend(); plt.show()                           # the gap between the two lines is the error
```
**Why:** Prints the error of one normal and one caught fraud against the threshold (normal 0.122 -> ok; fraud 8.585 -> FRAUD; threshold 2.052).

**Why not the alternative:** Not only the aggregate scores: one normal and one anomalous sample make the idea visible: small error = rebuilt well, large error = not rebuilt.

## 4. Terminology used in this notebook

| Term | Meaning |
|---|---|
| **Autoencoder** | A network trained to reproduce its input through a narrow middle layer (`fit(X, X)`), so it learns a compressed representation. |
| **Encoder / decoder** | The encoder compresses the input to a small code; the decoder rebuilds the input from the code. |
| **Bottleneck (latent code)** | The narrow middle layer. It must be smaller than the input, otherwise the network just copies. |
| **Reconstruction error** | How far the rebuilt sample is from the original (mean squared difference per sample). Large for anomalies. |
| **MSE** | Mean squared error: the average of `(input - reconstruction)^2`. The autoencoder loss. |
| **Threshold** | The error value above which a sample is called an anomaly. |
| **Anomaly** | A sample that does not look like normal data (fraud, abnormal heartbeat, faulty engine, unseen letter). |
| **Class imbalance** | One class is far rarer than the other (0.17 % fraud), so accuracy becomes meaningless. |
| **StandardScaler** | Subtracts the mean and divides by the standard deviation (mean 0, std 1). |
| **Data leakage** | Information from test data (or from the answer) leaking into training, for example fitting a scaler on all data or keeping RUL as an input. |
| **Linear activation** | No activation: the layer output is just the weighted sum. Used when outputs can be negative or large. |
| **ReLU** | `max(0, x)`. Cheap hidden-layer activation that does not saturate for positive values. |
| **Precision** | Of everything flagged positive, the fraction that really is positive: TP / (TP + FP). |
| **Recall** | Of all real positives, the fraction found: TP / (TP + FN). |
| **F1 score** | Harmonic mean of precision and recall: 2PR / (P + R). |
| **Confusion matrix** | Table of true class (rows) against predicted class (columns). The diagonal is correct. |
| **ROC-AUC** | Probability that a random anomaly gets a higher score than a random normal sample. 0.5 = guessing, 1.0 = perfect. Needs no threshold. |
| **Stratified split** | `stratify=y` keeps the class proportions the same in train and test. |

## 5. Theory you must be able to explain

**Anomaly detection with an autoencoder.** Train on normal data only. The network learns to rebuild normal transactions well. A fraud looks different, so it is rebuilt badly and gets a large error. Flag errors above a threshold.

**Why not a normal classifier.** With 0.17 % fraud a classifier can score 99.8 % by predicting 'normal' always, and there are too few frauds to learn from. The autoencoder needs no fraud examples to train.

**Reading precision and recall.** Precision 0.219: only about 1 flagged transaction in 5 is truly fraud (285 false alarms against 80 hits). Recall 0.816: it caught 80 of the 98 frauds. Raising the threshold gives fewer false alarms (precision up) but misses more fraud (recall down); it is a business trade-off.

**Threshold rules.** `mean + 3 std` assumes bell-shaped errors (not true here, errors are skewed); a percentile is adjustable; or choose the best F1 on a validation set. Always state the rule and its trade-off.

**Why the bottleneck must be small.** If it equalled the input size the network could copy everything, including fraud, and the detector would be useless.

## 6. Why we did this, and why not that

| Decision | Why we did it | Why not the alternative |
|---|---|---|
| Train on normal rows only | The model learns normal behaviour; fraud is then rebuilt badly | Training on all rows teaches it to rebuild fraud too |
| `StandardScaler` fitted on normal training rows | Features are unbounded and PCA-like; no leakage | MinMax with a sigmoid output does not suit negative values |
| Linear output layer | Standardised targets can be negative | Sigmoid cannot output negatives |
| Threshold mean + 3 std | Strict rule for a very rare class | 95th percentile flags thousands of normal transactions |
| Report precision / recall / F1 / AUC | Accuracy is 99.8 % for 'always normal' | Plain accuracy |
| Stratified split | Keeps the 0.17 % fraud rate in both parts | A random split could leave very few frauds in the test set |

## 7. Your result and how to read it

Threshold 2.052; 365 of 56,962 transactions flagged. Anomaly row: **precision 0.219, recall 0.816, F1 0.346**; confusion matrix `[[56579, 285], [18, 80]]`; **ROC-AUC 0.9337**. Accuracy is 0.995, which is exactly why it is not reported as the result.

Say it as: *"The autoencoder separates fraud with AUC 0.93 and catches 82 % of frauds, but only 22 % of alarms are real; I would choose the threshold from the cost of a missed fraud against a false alarm."*

## 8. Mistakes and traps (from your own notebooks)
- Forgetting `stratify=y`, or fitting the scaler on all rows.
- The AUC changes a little between runs (0.93-0.96) because the weights start randomly.
- A bigger network (24-14-7) is slightly steadier than 14-7; more epochs (60) did not help in my tests.

## 9. Viva questions with answers

**Q. Why train only on normal transactions?**

A. So normal is rebuilt well and fraud badly; then the error separates them.

**Q. Why not use accuracy?**

A. 99.83 % are normal, so 'always normal' scores 99.8 % and misses all fraud.

**Q. How did you choose the threshold?**

A. Mean + 3 std of the normal training errors, a strict rule for rare fraud; a percentile or best-F1 on validation are alternatives.

**Q. What do precision 0.22 and recall 0.82 mean?**

A. Of 365 alarms about 22 % are real fraud (80); of 98 frauds 82 % were caught.

**Q. What happens to precision and recall if the threshold is raised?**

A. Precision rises, recall falls.

**Q. Why is the output layer linear?**

A. The standardised features can be negative or large; sigmoid cannot reproduce them.

**Q. What is ROC-AUC?**

A. The probability that a random fraud has a larger error than a random normal transaction; 0.93 here.

**Q. What if the bottleneck were 30?**

A. The network could copy its input, so fraud would also be rebuilt well and detection would fail.
