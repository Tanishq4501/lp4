## 3. Notebook walkthrough: every cell, and why

### Cell 0: imports
```python
import tensorflow as tf
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.metrics import classification_report
```
**Why:** `tensorflow` is imported first (on this machine importing numpy or pandas before TensorFlow can crash the TensorFlow DLL). `classification_report` gives precision, recall and F1 per class; `matplotlib` draws the curves and the example image.

### Cell 1: alias for the layers module
```python
L = tf.keras.layers
```
**Why:** `L = tf.keras.layers` is only a short name so each layer is written `L.Dense(...)` instead of `tf.keras.layers.Dense(...)`.

### Cell 2: load the data
```python
tr = pd.read_csv("mnist_train.csv")
te = pd.read_csv("mnist_test.csv")
Xtr,ytr = tr.drop(columns="label").values.reshape(-1,28,28,1) / 255, tr.label.values
Xte,yte = te.drop(columns="label").values.reshape(-1,28,28,1) / 255, te.label.values
```
**Why:** Same loading as 1A. The `(28,28,1)` shape matters now: `Conv2D` needs the image shape with a channel axis (no Flatten at the start).

**Why not the alternative:** Not `to_categorical` (one-hot labels): the sparse loss accepts the integer labels directly, so no conversion is needed. Not skipping `/ 255`: unscaled pixels (0-255) make training slow and unstable.

### Cell 3: define the model (CNN)
```python
model = tf.keras.Sequential([L.Conv2D(32, 3, activation="relu"), L.MaxPooling2D(), L.Conv2D(64, 3, activation="relu"), L.MaxPooling2D(),
                             L.Flatten(), L.Dense(128, activation="relu"), L.Dense(10, activation="softmax")])
model.summary()
```
**Why:** Two `Conv2D` layers (32 then 64 filters of 3x3, ReLU) find local patterns; each `MaxPooling2D` halves the size; `Flatten` + `Dense(128)` combines the patterns; the last `Dense` with `softmax` gives class probabilities. Shapes: 28x28x1 -> `Conv2D(32,3)` 26x26x32 -> pool 13x13x32 -> `Conv2D(64,3)` 11x11x64 -> pool 5x5x64 -> Flatten 1,600 -> Dense 128 -> Dense 10. Parameters: 320 + 18,496 + 204,928 + 1,290 = **225,034**.

**Why not the alternative:** Not an FNN: it ignores where pixels are and has far more parameters for images. Not `padding="same"` or more layers: the simple version already works and is easy to explain and count.

### Cell 4: compile and train
```python
model.compile(optimizer="adam", loss="sparse_categorical_crossentropy", metrics=["accuracy"])
h = model.fit(Xtr, ytr, epochs=5, batch_size=128, validation_data=(Xte, yte))
```
**Why:** Adam, sparse categorical cross-entropy, **5 epochs**, batch 128. Five epochs are enough because a CNN learns MNIST very quickly (98.4 % after the first epoch).

**Why not the alternative:** Not SGD or 11 epochs: not needed here. Not more epochs: validation accuracy peaks at epoch 4 (99.01 %) and then dips slightly.

### Cell 5: evaluate
```python
print(model.evaluate(Xte, yte))                                  
print(classification_report(yte, model.predict(Xte).argmax(1)))
```
**Why:** `model.evaluate` returns `[test loss, test accuracy]`. `model.predict(Xte)` gives one probability per class and `.argmax(1)` picks the most probable class; `classification_report` then shows precision, recall and F1 per class so you can see which classes are weak.

**Why not the alternative:** Not accuracy alone: it hides which classes fail (digit 5 is slightly weaker than the rest).

### Cell 6: training curves
```python
pd.DataFrame(h.history).plot(); 
plt.show()
```
**Why:** `pd.DataFrame(h.history).plot()` draws loss and accuracy for training and validation in one line. Both curves falling together is healthy; training much better than validation means over-fitting.

**Why not the alternative:** Not a separate plot call for each curve: the DataFrame draws all four lines at once.

### Cell 7: one example
```python
#one example
names = [str(k) for k in range(10)]
i = 0                                                          # any test image
p = model.predict(Xte[i:i+1])[0]                               # one probability per class
plt.imshow(Xte[i].squeeze(), cmap="gray"); plt.title(f"true {names[yte[i]]} | predicted {names[p.argmax()]} ({p.max():.0%})")
plt.show()
```
**Why:** Shows what a single prediction looks like: the model returns one probability per class, `argmax` gives the label and the title shows the confidence. It makes the idea concrete in the viva (an image goes in, probabilities come out).

**Why not the alternative:** Not only the aggregate accuracy: one visible example is easier to explain. 

## 4. Terminology used in this notebook

| Term | Meaning |
|---|---|
| **Conv2D** | A layer of small filters (for example 3x3) that slide over an image and detect local patterns. |
| **Filter / kernel** | The small weight window of a convolution layer. `Conv2D(32, 3)` learns 32 filters of size 3x3. |
| **Feature map** | The output of one filter: where its pattern was found in the input. |
| **Padding** | `valid` = no padding (output shrinks); `same` = zero-pad so the size is kept at stride 1. |
| **Stride** | How many positions the filter jumps each step; stride 2 halves the size. |
| **MaxPooling** | Keeps the maximum of each block (2x2): halves width and height, reduces computation, adds small shift invariance. |
| **Flatten** | Turns a 2-D or 3-D feature map into one long vector so Dense layers can use it. |
| **Dense layer** | A fully connected layer: every input connects to every unit. Parameters = `inputs * units + units`. |
| **ReLU** | `max(0, x)`. Cheap hidden-layer activation that does not saturate for positive values. |
| **Softmax** | Output activation that turns scores into probabilities that sum to 1 (one per class). |
| **Adam** | An optimiser that keeps running averages of the gradient and its square, so every weight gets its own adaptive step. Default learning rate 1e-3. |
| **Accuracy** | Correct predictions divided by all predictions. Misleading when classes are imbalanced. |
| **Precision** | Of everything flagged positive, the fraction that really is positive: TP / (TP + FP). |
| **Recall** | Of all real positives, the fraction found: TP / (TP + FN). |
| **F1 score** | Harmonic mean of precision and recall: 2PR / (P + R). |

## 5. Theory you must be able to explain

**Why a CNN does better than the FNN of 1A.** Convolutions find strokes and curves wherever they appear, and shared filters make the model smaller per feature: 98.9 % in 5 epochs against 94.3 % in 11.

**Output sizes.** `Conv2D(32,3)` without padding: `(28-3)/1+1 = 26`. Pooling 2x2 halves it (13). Next conv: 11; pool: floor(11/2) = 5. Flatten: 5x5x64 = 1,600.

**Parameters.** Conv1: (3*3*1+1)*32 = 320; conv2: (3*3*32+1)*64 = 18,496; dense: 1,600*128+128 = 204,928; output: 1,290. Total 225,034; most are in the first Dense layer.

**Why it already works with 5 epochs.** MNIST is easy and Adam adapts quickly; extra epochs add little (and the curve flattens).

## 6. Why we did this, and why not that

| Decision | Why we did it | Why not the alternative |
|---|---|---|
| CNN instead of FNN | Exploits image structure: higher accuracy with fewer epochs | FNN (1A) is the baseline |
| Adam, 5 epochs | Converges fast on MNIST | SGD and 11 epochs are for 1A |
| Keep `(28,28,1)` | Conv2D needs a channel axis | No Flatten before the first conv |
| No padding, no Dropout | Simplest working model; sizes are easy to compute | Add Dropout only if over-fitting appears (it does not) |

## 9. Viva questions with answers

**Q. Why is a CNN better for images?**

A. Local filters detect patterns anywhere, weights are shared, and pooling adds shift invariance.

**Q. How many parameters does the first conv layer have?**

A. (3x3x1+1)x32 = 320.

**Q. Output shape after the second pooling?**

A. 5x5x64, which flattens to 1,600.

**Q. Why only 5 epochs?**

A. A CNN on MNIST converges fast; validation accuracy peaks at epoch 4.

**Q. Compare with 1A.**

A. 98.9 % in 5 epochs against 94.3 % in 11 epochs with an FNN and SGD.

**Q. What would you do if it over-fitted?**

A. Dropout, augmentation, early stopping.
