# PS 1A: Feed-forward network on handwritten MNIST (SGD, 11 epochs)

## 1. What the PS asks (in plain words)
Build a feed-forward neural network that recognises handwritten digits 0-9. The PS lists the steps: import the packages, load the training and test data, define the architecture, train with the **SGD** optimiser for **11 epochs**, evaluate, and plot the training loss and accuracy.

## 2. Dataset
- MNIST handwritten digits: 60,000 training and 10,000 test images, 28x28 grey pixels, 10 classes (0-9).
- CSV format: the first column is `label`, then 784 pixel columns (0-255). Files: `mnist_train.csv`, `mnist_test.csv`.

## 3. Notebook walkthrough: every cell, and why

### Cell 0: imports
```python
import tensorflow as tf
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.metrics import classification_report
```
**Why:** `tensorflow` is imported first (on this machine importing numpy or pandas before TensorFlow can crash the TensorFlow DLL). `classification_report` gives precision, recall and F1 per class; `matplotlib` draws the curves and the example image.

### Cell 1: alias for the layers module
```python
L = tf.keras.layers
```
**Why:** `L = tf.keras.layers` is only a short name so each layer is written `L.Dense(...)` instead of `tf.keras.layers.Dense(...)`.

### Cell 2: load the data
```python
tr = pd.read_csv("mnist_train.csv")
te = pd.read_csv("mnist_test.csv")
Xtr,ytr = tr.drop(columns="label").values.reshape(-1,28,28,1) / 255, tr.label.values
Xte,yte = te.drop(columns="label").values.reshape(-1,28,28,1) / 255, te.label.values
```
**Why:** Each row is one image: the `label` column is the answer and the other 784 columns are pixels. `.reshape(-1,28,28,1)` rebuilds the 28x28 picture with one grey channel, and `/ 255` scales pixels to 0-1. The test file is passed as `validation_data` because the PS gives only train and test files.

**Why not the alternative:** Not `to_categorical` (one-hot labels): the sparse loss accepts the integer labels directly, so no conversion is needed. Not skipping `/ 255`: unscaled pixels (0-255) make training slow and unstable.

### Cell 3: define the model (FNN)
```python
model = tf.keras.Sequential([L.Flatten(), L.Dense(256, activation="relu"), L.Dense(128, activation="relu"), L.Dense(10, activation="softmax")])
model.summary()
```
**Why:** `Flatten` turns the image into one long vector; two `Dense` layers with ReLU (256 then 128 units) learn combinations of pixels; the last `Dense` has one unit per class with `softmax`, so the outputs are probabilities that sum to 1. Parameters: 784x256+256 = 200,960, 256x128+128 = 32,896, 128x10+10 = 1,290, total **235,146** (check with `model.summary()`).

**Why not the alternative:** Not more or bigger layers: this size is enough to show the effect and trains in seconds. Not `sigmoid` or no activation at the end: softmax is the right output for exactly one correct class among several.

### Cell 4: compile and train
```python
model.compile(optimizer="sgd", loss="sparse_categorical_crossentropy", metrics=["accuracy"])
h = model.fit(Xtr, ytr, epochs=11, batch_size=128, validation_data=(Xte, yte))
```
**Why:** `optimizer="sgd"` because the PS asks for SGD (default learning rate 0.01). `sparse_categorical_crossentropy` because labels are integers 0-9. `epochs=11` is the PS value. `batch_size=128` gives `60000/128` = 469 iterations per epoch (your log shows `469/469`). `validation_data=(Xte, yte)` reports test loss and accuracy after every epoch.

**Why not the alternative:** Not Adam: the PS names SGD (Adam would reach about 97 % in the same time, which is a nice point to mention). Not more epochs: 11 is the PS number, although accuracy is still slowly rising.

### Cell 5: evaluate
```python
print(model.evaluate(Xte, yte))                                  
print(classification_report(yte, model.predict(Xte).argmax(1)))
```
**Why:** `model.evaluate` returns `[test loss, test accuracy]`. `model.predict(Xte)` gives one probability per class and `.argmax(1)` picks the most probable class; `classification_report` then shows precision, recall and F1 per class so you can see which classes are weak.

**Why not the alternative:** Not accuracy alone: it hides which classes fail (digit 8 and 3 are the weakest here).

### Cell 6: training curves
```python
pd.DataFrame(h.history).plot(); 
plt.show()
```
**Why:** `pd.DataFrame(h.history).plot()` draws loss and accuracy for training and validation in one line. Both curves falling together is healthy; training much better than validation means over-fitting.

**Why not the alternative:** Not a separate plot call for each curve: the DataFrame draws all four lines at once.

### Cell 7: one example
```python
#one example
names = [str(k) for k in range(10)]
i = 0                                                          # any test image
p = model.predict(Xte[i:i+1])[0]                               # one probability per class
plt.imshow(Xte[i].squeeze(), cmap="gray"); plt.title(f"true {names[yte[i]]} | predicted {names[p.argmax()]} ({p.max():.0%})")
plt.show()
```
**Why:** Shows what a single prediction looks like: the model returns one probability per class, `argmax` gives the label and the title shows the confidence. It makes the idea concrete in the viva (an image goes in, probabilities come out).

**Why not the alternative:** Not only the aggregate accuracy: one visible example is easier to explain. 

## 4. Terminology used in this notebook

| Term | Meaning |
|---|---|
| **Epoch** | One full pass of the training data through the network. |
| **Batch / batch size** | The number of samples used for one weight update (128 or 64 here; 32 for image folders). |
| **Iteration** | One weight update on one batch. Iterations per epoch = samples / batch size. |
| **SGD** | Stochastic gradient descent: `w = w - lr * gradient` with one global learning rate (Keras default 0.01). |
| **Loss function** | One number that says how wrong the predictions are; training minimises it. |
| **Sparse categorical cross-entropy** | Multi-class loss `-log(probability of the true class)` that takes integer labels (7) instead of one-hot vectors. |
| **Softmax** | Output activation that turns scores into probabilities that sum to 1 (one per class). |
| **ReLU** | `max(0, x)`. Cheap hidden-layer activation that does not saturate for positive values. |
| **Dense layer** | A fully connected layer: every input connects to every unit. Parameters = `inputs * units + units`. |
| **Flatten** | Turns a 2-D or 3-D feature map into one long vector so Dense layers can use it. |
| **Normalisation (/255)** | Dividing pixels by 255 so inputs are in 0..1: small, similar-sized inputs give stable, faster training. |
| **Validation data** | Data the model does not train on, used to watch progress. In the classifier notebooks the PS gives only train and test files, so the test file is used as validation. |
| **Accuracy** | Correct predictions divided by all predictions. Misleading when classes are imbalanced. |
| **Precision** | Of everything flagged positive, the fraction that really is positive: TP / (TP + FP). |
| **Recall** | Of all real positives, the fraction found: TP / (TP + FN). |
| **F1 score** | Harmonic mean of precision and recall: 2PR / (P + R). |
| **Support** | How many true samples of each class are in the test data. |
| **Macro / weighted average** | Macro = plain average over classes; weighted = average weighted by class size. |

## 5. Theory you must be able to explain

**How an FNN classifies an image.** The 28x28 image is flattened to 784 numbers. Each Dense layer computes `activation(W x + b)`. The last layer gives 10 scores; softmax turns them into probabilities; the digit with the highest probability is the prediction.

**How it learns.** The loss (cross-entropy) is large when the true digit gets a low probability. Backpropagation computes the gradient of the loss with respect to every weight; SGD moves each weight a small step against its gradient. One pass over the data is an epoch.

**SGD vs Adam.** SGD uses one fixed learning rate for all weights and needs more epochs; Adam adapts the step per weight and converges faster. That is why accuracy is still rising at epoch 11 with SGD.

**Why validation curves matter.** If training accuracy keeps rising while validation accuracy stalls, the model over-fits. Here both rise together, so there is no over-fitting.

## 6. Why we did this, and why not that

| Decision | Why we did it | Why not the alternative |
|---|---|---|
| Flatten the image | Dense layers need a vector | Not a CNN: this PS is the FNN baseline; 2B repeats the task with a CNN |
| Scale pixels by 255 | Small inputs make gradient descent stable and fast | Without it accuracy collapses and loss starts high |
| Softmax + sparse categorical cross-entropy | One correct class out of 10; labels are integers | Not sigmoid + binary cross-entropy (that is for two classes) |
| SGD, 11 epochs | Required by the PS | Not Adam: faster, but not what is asked |
| Test file as validation data | Only train and test files are given | Not a separate validation split: the PS does not ask for it, but say honestly that the reported score is a test score |
| No Dropout | No over-fitting is visible, and the PS does not ask for it | Dropout is the first fix if validation falls behind |

## 9. Viva questions with answers

**Q. Why 10 output units with softmax?**

A. There are 10 digits; softmax makes the 10 outputs probabilities that sum to 1 and the largest is the prediction.

**Q. Why sparse categorical cross-entropy?**

A. Labels are integers (7), not one-hot vectors; the loss is the same, `-log(p of the true class)`.

**Q. What is an epoch, a batch and an iteration here?**

A. An epoch is one pass over 60,000 images; a batch is 128 images; an iteration is one update, so 469 per epoch.

**Q. SGD vs Adam?**

A. SGD uses one global learning rate; Adam keeps running averages of the gradient and its square and adapts each weight's step, so it converges faster.

**Q. How many parameters does your model have?**

A. 235,146: 200,960 + 32,896 + 1,290 (Dense: inputs x units + units).

**Q. How do you know it is not over-fitting?**

A. Training accuracy (93.8 %) and validation accuracy (94.3 %) are close and both still rising.

**Q. Which digit is hardest and why?**

A. 8, because it shares strokes with 3, 5 and 9; its F1 is 0.92.

**Q. Why is the test set used as validation data?**

A. The PS gives only train and test files; the number is therefore a test score and I state that.
