## 1. What the PS asks (in plain words)
The same pipeline as 1A on a harder dataset: clothing images. Load the data, define an FNN, train with SGD, evaluate and plot loss and accuracy.

## 2. Dataset
- Fashion-MNIST: 60,000 training and 10,000 test images, 28x28 grey, 10 clothing classes: T-shirt/top, Trouser, Pullover, Dress, Coat, Sandal, Shirt, Sneaker, Bag, Ankle boot.
- CSV format like MNIST: `label` first, then 784 pixels. Files: `fashion-mnist_train.csv`, `fashion-mnist_test.csv`.

## 3. Notebook walkthrough: every cell, and why

### Cell 0: imports
```python
import tensorflow as tf
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.metrics import classification_report
```
**Why:** `tensorflow` is imported first (on this machine importing numpy or pandas before TensorFlow can crash the TensorFlow DLL). `classification_report` gives precision, recall and F1 per class; `matplotlib` draws the curves and the example image.

### Cell 1: alias for the layers module
```python
L = tf.keras.layers
```
**Why:** `L = tf.keras.layers` is only a short name so each layer is written `L.Dense(...)` instead of `tf.keras.layers.Dense(...)`.

### Cell 2: load the data
```python
tr = pd.read_csv("fashion-mnist_train.csv")
te = pd.read_csv("fashion-mnist_test.csv")
Xtr,ytr = tr.drop(columns="label").values.reshape(-1,28,28,1) / 255, tr.label.values
Xte,yte = te.drop(columns="label").values.reshape(-1,28,28,1) / 255, te.label.values
```
**Why:** Same loading as 1A: `label` column is the class (0-9), the rest are pixels reshaped to 28x28x1 and divided by 255.

**Why not the alternative:** Not `to_categorical` (one-hot labels): the sparse loss accepts the integer labels directly, so no conversion is needed. Not skipping `/ 255`: unscaled pixels (0-255) make training slow and unstable.

### Cell 3: define the model (FNN)
```python
model = tf.keras.Sequential([L.Flatten(), L.Dense(256, activation="relu"), L.Dense(128, activation="relu"), L.Dense(10, activation="softmax")])
model.summary()
```
**Why:** `Flatten` turns the image into one long vector; two `Dense` layers with ReLU (256 then 128 units) learn combinations of pixels; the last `Dense` has one unit per class with `softmax`, so the outputs are probabilities that sum to 1. It is exactly the 1A network (235,146 parameters), so any accuracy difference comes from the data, not the model.

**Why not the alternative:** Not more or bigger layers: this size is enough to show the effect and trains in seconds. Not `sigmoid` or no activation at the end: softmax is the right output for exactly one correct class among several.

### Cell 4: compile and train
```python
model.compile(optimizer="sgd", loss="sparse_categorical_crossentropy", metrics=["accuracy"])
h = model.fit(Xtr, ytr, epochs=11, batch_size=128, validation_data=(Xte, yte))
```
**Why:** SGD (default learning rate 0.01), sparse categorical cross-entropy, 11 epochs, batch 128, test data as validation. Same settings as 1A on purpose, so the two results can be compared.

**Why not the alternative:** Not Adam: the PS asks for SGD. Not more epochs: accuracy is still creeping up (85.1 % to 85.6 % in the last epoch), which is a sign SGD is slow.

### Cell 5: evaluate
```python
print(model.evaluate(Xte, yte))                                  
print(classification_report(yte, model.predict(Xte).argmax(1)))
```
**Why:** `model.evaluate` returns `[test loss, test accuracy]`. `model.predict(Xte)` gives one probability per class and `.argmax(1)` picks the most probable class; `classification_report` then shows precision, recall and F1 per class so you can see which classes are weak.

**Why not the alternative:** Not accuracy alone: it hides which classes fail (Shirt is the weakest class because it looks like T-shirt and Pullover).

### Cell 6: training curves
```python
pd.DataFrame(h.history).plot(); 
plt.show()
```
**Why:** `pd.DataFrame(h.history).plot()` draws loss and accuracy for training and validation in one line. Both curves falling together is healthy; training much better than validation means over-fitting.

**Why not the alternative:** Not a separate plot call for each curve: the DataFrame draws all four lines at once.

### Cell 7: one example
```python
#one example
names = ["T-shirt","Trouser","Pullover","Dress","Coat","Sandal","Shirt","Sneaker","Bag","Ankle boot"]
i = 0                                                          # any test image
p = model.predict(Xte[i:i+1])[0]                               # one probability per class
plt.imshow(Xte[i].squeeze(), cmap="gray"); plt.title(f"true {names[yte[i]]} | predicted {names[p.argmax()]} ({p.max():.0%})")
plt.show()
```
**Why:** Shows what a single prediction looks like: the model returns one probability per class, `argmax` gives the label and the title shows the confidence. It makes the idea concrete in the viva (an image goes in, probabilities come out).

**Why not the alternative:** Not only the aggregate accuracy: one visible example is easier to explain. 

## 4. Terminology used in this notebook

| Term | Meaning |
|---|---|
| **Epoch** | One full pass of the training data through the network. |
| **Batch / batch size** | The number of samples used for one weight update (128 or 64 here; 32 for image folders). |
| **SGD** | Stochastic gradient descent: `w = w - lr * gradient` with one global learning rate (Keras default 0.01). |
| **Sparse categorical cross-entropy** | Multi-class loss `-log(probability of the true class)` that takes integer labels (7) instead of one-hot vectors. |
| **Softmax** | Output activation that turns scores into probabilities that sum to 1 (one per class). |
| **ReLU** | `max(0, x)`. Cheap hidden-layer activation that does not saturate for positive values. |
| **Dense layer** | A fully connected layer: every input connects to every unit. Parameters = `inputs * units + units`. |
| **Flatten** | Turns a 2-D or 3-D feature map into one long vector so Dense layers can use it. |
| **Normalisation (/255)** | Dividing pixels by 255 so inputs are in 0..1: small, similar-sized inputs give stable, faster training. |
| **Accuracy** | Correct predictions divided by all predictions. Misleading when classes are imbalanced. |
| **Precision** | Of everything flagged positive, the fraction that really is positive: TP / (TP + FP). |
| **Recall** | Of all real positives, the fraction found: TP / (TP + FN). |
| **F1 score** | Harmonic mean of precision and recall: 2PR / (P + R). |
| **Confusion matrix** | Table of true class (rows) against predicted class (columns). The diagonal is correct. |
| **Support** | How many true samples of each class are in the test data. |

## 5. Theory you must be able to explain

**Why Fashion-MNIST is harder than MNIST.** Digits are thin strokes with clear shapes; clothes share textures and outlines (a Shirt, T-shirt, Pullover and Coat are all torso shapes). A plain FNN with no notion of local patterns separates them less well.

**Per-class metrics.** The classification report shows that Trouser (F1 0.97), Bag (0.95) and the footwear classes (0.91-0.93) are easy, while Shirt (0.64), Pullover (0.76) and Coat (0.79) are hard. Always look at the weakest classes, not only the average.

**Why the loss is higher than in 1A.** Cross-entropy was 0.42 here against 0.21 for MNIST: the model is less sure of the correct class.

## 6. Why we did this, and why not that

| Decision | Why we did it | Why not the alternative |
|---|---|---|
| Same FNN as 1A | A fair comparison across datasets | Not a bigger network: the PS asks for the same kind of model |
| SGD, 11 epochs | Required by the PS | Not Adam |
| Report per-class scores | Shows Shirt, Pullover and Coat are the weak classes | Not only accuracy: it would hide this |
| `/ 255` and reshape | Same preprocessing as MNIST | No extra normalisation is needed for grey images |

## 7. Your result and how to read it

**Test accuracy 85.55 %**, test loss 0.4218. Training accuracy at the end is 85.4 %, so no over-fitting. Best classes: Trouser (F1 0.97), Bag (0.95). Weakest: **Shirt (F1 0.64, precision 0.66, recall 0.62)**, then Pullover (0.76) and Coat (0.79).

Say it as: *"The same FNN drops from 94 % on digits to 85.6 % on clothes; Shirt is confused with T-shirt and Pullover. Accuracy is still rising, so SGD would benefit from more epochs."*

**Q. Why is Fashion-MNIST harder than MNIST?**

A. Clothing classes share textures and outlines, so they overlap more than digits.

**Q. Which class is the hardest?**

A. Shirt (F1 0.64): it looks like T-shirt, Pullover and Coat.

**Q. Same model, lower accuracy: what does that tell you?**

A. That the data, not the architecture, limits the result; a CNN would help.

**Q. Is the model over-fitting?**

A. No: training accuracy (85.4 %) is about the same as validation (85.6 %).

**Q. Why SGD and not Adam?**

A. The PS specifies SGD; Adam converges faster and would likely score higher.

**Q. What is a confusion matrix and what would it show here?**

A. True class against predicted class; large off-diagonal cells such as Shirt-predicted-as-T-shirt.
