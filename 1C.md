## 1. What the PS asks (in plain words)
Classify colour photos of 10 object types with an FNN: load the data, define the architecture, train (SGD or Adam), evaluate and plot loss and accuracy.

## 2. Dataset
- CIFAR-10: 32x32 colour images in 10 classes: airplane, automobile, bird, cat, deer, dog, frog, horse, ship, truck.
- Your folder has **one file**, `cifar-10.csv`, with 50,000 rows: 3,072 pixel columns (`pixel_0` ... `pixel_3071`) and `label` as the **last** column. There is no test file, so you split it 80/20 (40,000 train, 10,000 test).
- Pixels are stored as **three colour planes** (all red values, then green, then blue).

## 3. Notebook walkthrough: every cell, and why

### Cell 0: imports
```python
import tensorflow as tf
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.metrics import classification_report
from sklearn.model_selection import train_test_split
```
**Why:** `tensorflow` is imported first (on this machine importing numpy or pandas before TensorFlow can crash the TensorFlow DLL). `classification_report` gives precision, recall and F1 per class; `matplotlib` draws the curves and the example image. `train_test_split` is needed here because the CIFAR CSV has no separate test file.

### Cell 1: alias for the layers module
```python
L = tf.keras.layers
```
**Why:** `L = tf.keras.layers` is only a short name so each layer is written `L.Dense(...)` instead of `tf.keras.layers.Dense(...)`.

### Cell 2: read the CIFAR CSV
```python
df = pd.read_csv("cifar-10.csv",dtype=np.uint8)
df.head()
```
**Why:** `pd.read_csv(..., dtype=np.uint8)` reads the 50,000 x 3,073 table as small integers. `df.head()` is only a look at the data (label is the last column).

**Why not the alternative:** Not reading as the default int64: `dtype=np.uint8` keeps the 50,000 x 3,073 table small in memory.

### Cell 3: reshape to images, scale, split 80/20
```python
X = df.drop(columns="label").values.reshape(-1,3,32,32).transpose(0,2,3,1).astype("float32") / 255
Xtr,Xte,ytr,yte = train_test_split(X,df.label.values.astype(int),test_size=0.2,random_state=42)
```
**Why:** `.reshape(-1,3,32,32)` rebuilds the three colour planes, `.transpose(0,2,3,1)` moves colour to the last axis to get the normal `(N,32,32,3)` image layout, `.astype("float32") / 255` scales to 0-1. `train_test_split(test_size=0.2, random_state=42)` makes the missing test set (fixed seed so the split is repeatable); `.astype(int)` converts the labels from uint8 to normal integers.

**Why not the alternative:** Not `reshape(-1,32,32,3)` directly: the pixels are stored as three colour planes (all R, then all G, then all B), so a direct reshape would scramble the colours. Not skipping the split: there is no test file, so we make one.

### Cell 4: define the model (FNN)
```python
model = tf.keras.Sequential([L.Flatten(), L.Dense(256, activation="relu"), L.Dense(128, activation="relu"), L.Dense(10, activation="softmax")])
model.summary()
```
**Why:** `Flatten` turns the image into one long vector; two `Dense` layers with ReLU (256 then 128 units) learn combinations of pixels; the last `Dense` has one unit per class with `softmax`, so the outputs are probabilities that sum to 1. `Flatten` now produces 3,072 inputs. Parameters: 3072x256+256 = 786,688, 256x128+128 = 32,896, 128x10+10 = 1,290, total **820,874**, many more than for MNIST.

**Why not the alternative:** Not more or bigger layers: this size is enough to show the effect and trains in seconds. Not `sigmoid` or no activation at the end: softmax is the right output for exactly one correct class among several.

### Cell 5: compile and train
```python
model.compile(optimizer="adam", loss="sparse_categorical_crossentropy", metrics=["accuracy"])
h = model.fit(Xtr, ytr, epochs=10, batch_size=128, validation_data=(Xte, yte))
```
**Why:** `adam`: an adaptive optimiser, which learns faster on this harder data (the PS allows SGD or Adam). Sparse categorical cross-entropy, 10 epochs, batch 128, test data as validation.

**Why not the alternative:** Not SGD: with only 10 epochs it would be slower to converge on colour images. Not more epochs: the FNN's ceiling is low, so more epochs mostly give over-fitting.

### Cell 6: evaluate
```python
print(model.evaluate(Xte, yte))                                  
print(classification_report(yte, model.predict(Xte).argmax(1)))
```
**Why:** `model.evaluate` returns `[test loss, test accuracy]`. `model.predict(Xte)` gives one probability per class and `.argmax(1)` picks the most probable class; `classification_report` then shows precision, recall and F1 per class so you can see which classes are weak.

**Why not the alternative:** Not accuracy alone: it hides which classes fail (cat, bird, deer and dog are the weakest).

### Cell 7: training curves
```python
pd.DataFrame(h.history).plot(); 
plt.show()
```
**Why:** `pd.DataFrame(h.history).plot()` draws loss and accuracy for training and validation in one line. Both curves falling together is healthy; training much better than validation means over-fitting.

**Why not the alternative:** Not a separate plot call for each curve: the DataFrame draws all four lines at once.

### Cell 9: one example
```python
#one example
names = ["airplane","automobile","bird","cat","deer","dog","frog","horse","ship","truck"]
i = 0                                                          # any test image
p = model.predict(Xte[i:i+1])[0]                               # one probability per class
plt.imshow(Xte[i].squeeze(), cmap="gray"); plt.title(f"true {names[yte[i]]} | predicted {names[p.argmax()]} ({p.max():.0%})")
plt.show()
```
**Why:** Shows what a single prediction looks like: the model returns one probability per class, `argmax` gives the label and the title shows the confidence. It makes the idea concrete in the viva (an image goes in, probabilities come out).

**Why not the alternative:** Not only the aggregate accuracy: one visible example is easier to explain. CIFAR examples are often wrong because the model is weak (47 %), which is itself a good talking point.

## 4. Terminology used in this notebook

| Term | Meaning |
|---|---|
| **Adam** | An optimiser that keeps running averages of the gradient and its square, so every weight gets its own adaptive step. Default learning rate 1e-3. |
| **Sparse categorical cross-entropy** | Multi-class loss `-log(probability of the true class)` that takes integer labels (7) instead of one-hot vectors. |
| **Softmax** | Output activation that turns scores into probabilities that sum to 1 (one per class). |
| **ReLU** | `max(0, x)`. Cheap hidden-layer activation that does not saturate for positive values. |
| **Dense layer** | A fully connected layer: every input connects to every unit. Parameters = `inputs * units + units`. |
| **Flatten** | Turns a 2-D or 3-D feature map into one long vector so Dense layers can use it. |
| **Normalisation (/255)** | Dividing pixels by 255 so inputs are in 0..1: small, similar-sized inputs give stable, faster training. |
| **Over-fitting** | The model memorises the training data and does worse on new data: training score keeps rising, validation score stalls. |
| **Accuracy** | Correct predictions divided by all predictions. Misleading when classes are imbalanced. |
| **Precision** | Of everything flagged positive, the fraction that really is positive: TP / (TP + FP). |
| **Recall** | Of all real positives, the fraction found: TP / (TP + FN). |
| **F1 score** | Harmonic mean of precision and recall: 2PR / (P + R). |
| **Support** | How many true samples of each class are in the test data. |
| **Confusion matrix** | Table of true class (rows) against predicted class (columns). The diagonal is correct. |
| **train_test_split** | scikit-learn helper that randomly splits data into train and test parts; `random_state` makes the split repeatable. |

## 5. Theory you must be able to explain

**Why an FNN does badly on CIFAR-10.** Flattening destroys where things are in the picture: a cat in the corner and a cat in the centre become different inputs. 3,072 raw colour values per image, about 820,000 parameters and no translation invariance make the model weak. A CNN (2A) fixes this.

**Under-fitting, not over-fitting.** Training accuracy at the end is 48.5 % and validation 46.7 %: both are low. The limit is the model type, not too much training.

**Colour plane layout.** The CSV stores all red values, then green, then blue. The reshape-and-transpose trick turns that into normal `(32,32,3)` images; reshaping directly would mix up the colours.

## 6. Why we did this, and why not that

| Decision | Why we did it | Why not the alternative |
|---|---|---|
| Reshape `(3,32,32)` then transpose | Matches how the CSV stores the colours | A direct `(32,32,3)` reshape scrambles the channels |
| 80/20 split of one file | There is no test file | Not training on everything: we would have nothing to test on |
| Adam | Faster convergence on harder data | SGD needs more epochs |
| Same FNN as 1A | Shows what an FNN can do on images | A CNN is the next PS (2A) |
| `dtype=np.uint8` when reading | Keeps memory small | Default int64 would use 8 times more memory |

## 7. Your result and how to read it

**Test accuracy 46.74 %**, test loss 1.4918, far below MNIST. Weakest classes: **cat (F1 0.32)**, bird, deer and dog (0.39); best: ship (0.59) and automobile (0.58).

Say it as: *"An FNN reaches only 47 % on CIFAR-10 because flattening discards spatial structure. The CNN in 2A reaches about 70 % on the same data."*

## 8. Mistakes and traps (from your own notebooks)
- Reshaping directly to `(32,32,3)` gives wrong colours: use `(3,32,32)` then `transpose(0,2,3,1)`.
- Without `.astype(int)` the labels stay `uint8`.

## 9. Viva questions with answers

**Q. Why does an FNN fail on CIFAR-10?**

A. It flattens the image, loses spatial structure, has no translation invariance and uses many parameters on raw pixels.

**Q. How is a CIFAR row stored and how did you reshape it?**

A. As red, green and blue planes; `reshape(-1,3,32,32).transpose(0,2,3,1)` gives `(N,32,32,3)`.

**Q. Why did you make a split yourself?**

A. The folder has one CSV and no test file, so I used 80/20 with a fixed random state.

**Q. Is it over-fitting?**

A. No: training 48.5 % and validation 46.7 % are both low, so it is under-fitting due to the model type.

**Q. Why Adam here?**

A. It adapts step sizes and converges faster than SGD in 10 epochs; the PS allows either.

**Q. Parameter count?**

A. 820,874: 786,688 + 32,896 + 1,290.

**Q. Which class is hardest?**

A. Cat (F1 0.32): it looks like dog and other small animals.
