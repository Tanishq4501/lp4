## 1. What the PS asks (in plain words)
Build a simple recommendation system: collect and pre-process documents, train CBOW embeddings, represent every document as a vector, and recommend the documents most similar to a query using cosine similarity.

## 2. Dataset
- The same `twitter_dataset.csv` (10,000 tweets of random words): each tweet is a **document**.
- Document matrix `D` has shape `(10000, 100)`: one vector per tweet.

## 3. Notebook walkthrough: every cell, and why

### Cell 0: imports
```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from gensim.models import Word2Vec
from gensim.utils import simple_preprocess
from gensim.parsing.preprocessing import remove_stopwords
from sklearn.metrics.pairwise import cosine_similarity
```
**Why:** `gensim` provides `Word2Vec`; `simple_preprocess` lowercases and splits text into words; `remove_stopwords` deletes very common words; `numpy`/`pandas` hold the data and `matplotlib` plots. `cosine_similarity` from scikit-learn compares the query vector with all document vectors at once.

### Cell 1: load the documents
```python
tw = pd.read_csv("twitter_dataset.csv")
tw.head()
```
**Why:** Reads the tweets; each row's `Text` is a document.

### Cell 2: pre-process and train CBOW
```python
tok = [simple_preprocess(remove_stopwords(t.lower())) for t in tw.Text]
wv = Word2Vec(tok,vector_size=100,window=5,min_count=2,sg=0,epochs=30).wv
```
**Why:** Same as 4B: lowercase, remove stop words, tokenise, train CBOW (`vector_size=100`, `window=5`, `min_count=2`, `epochs=30`).

**Why not the alternative:** Not skip-gram; not a different corpus for the query words: one embedding space for both.

### Cell 3: document vectors
```python
vec = lambda ws: np.mean([wv[w] for w in ws if w in wv] or [np.zeros(100)],axis=0)    # document = average of its word vectors
D = np.array([vec(t) for t in tok])
print(D.shape)
```
**Why:** `vec` averages the vectors of a document's words (zero vector if none); `D` stacks them: `(10000, 100)`. Every document and every query now lives in the same 100-dimensional space.

**Why not the alternative:** Not a count vector: it would not capture similar meaning. Averaging loses word order (acceptable here).

### Cell 4: recommend
```python
query = " ".join(wv.index_to_key[:3])                  # replace with your own words
s = cosine_similarity([vec(simple_preprocess(query))],D)[0]          # similarity of the query to EVERY tweet
top = s.argsort()[::-1][:5]                            # indices of the 5 most similar
print(query)
print(tw.Text.iloc[top].str.replace("\n"," ").to_string(),"\n",s[top])
```
**Why:** The query is the 3 most frequent words (`hard tax add`); `cosine_similarity([query], D)` gives the similarity to **every** tweet; `argsort()[::-1][:5]` takes the 5 largest. Your top scores: 0.445, 0.440, 0.439, 0.434, 0.423, and the top tweets contain `hard` and `tax`.

**Why not the alternative:** Not Euclidean distance: it depends on vector length (document length); cosine looks at direction. Not sorting by a hand-made score.

### Cell 5: similarity bar plot
```python
plt.barh(range(5),s[top])
plt.xlabel("cosine similarity")
plt.show()
```
**Why:** `barh` shows the 5 similarity scores: how close the recommendations are.

**Why not the alternative:** Not only the text: the scores tell how confident each recommendation is.

## 4. Terminology used in this notebook

| Term | Meaning |
|---|---|
| **Word embedding** | A dense vector (for example 100 numbers) for a word; words used in similar contexts get similar vectors. |
| **CBOW** | Continuous Bag of Words (`sg=0`): the averaged context words predict the centre word. Fast, good for frequent words. |
| **Word2Vec** | An algorithm (Mikolov, 2013) that learns word embeddings from a prediction task on text; gensim implements it. |
| **Document vector** | The average of the word vectors of a document. |
| **Cosine similarity** | The cosine of the angle between two vectors: (a . b) divided by (length of a x length of b). 1 = same direction, 0 = unrelated. |
| **Content-based recommender** | Recommends items whose content vector is most similar to a query or to what the user liked. |
| **Stop words** | Very common words ('the', 'and') that carry little meaning and are removed. |
| **Tokenisation** | Splitting text into words (`simple_preprocess` also lowercases and drops punctuation). |
| **min_count** | Words rarer than this are ignored (2 for tweets, 5 for IMDB, 1 for the tiny document). |
| **Vocabulary** | The set of distinct words that received a vector. |

## 5. Theory you must be able to explain

**Content-based recommendation.** Represent every item by a vector built from its content; recommend the items closest to a query or to what the user liked.

**Document vector.** The average of its word vectors. It places every document in the same space as the query, so one similarity computation ranks all of them.

**Cosine similarity.** `(a . b) / (|a||b|)` = cosine of the angle; 1 means the same direction. It is preferred to Euclidean distance because long and short documents with the same topic have similar direction but different lengths.

**Versus collaborative filtering.** Collaborative filtering uses user-item interactions (ratings, clicks) and needs no content; content-based works for new items (no cold start) but only recommends similar things.

**Why your scores are low (about 0.44).** The tweets are random words, so no document is truly similar to the query; the ranking still works mechanically.

## 6. Why we did this, and why not that

| Decision | Why we did it | Why not the alternative |
|---|---|---|
| Average word vectors per document | A simple, fast document representation in the embedding space | Loses word order; Doc2Vec or TF-IDF weighting are alternatives |
| Cosine similarity | Ignores document length | Euclidean distance is length-sensitive |
| Query of frequent words | Always in the vocabulary | A word outside the vocabulary is skipped by the `if w in wv` guard |
| Top-5 by `argsort` | Simple ranking | No need for a library |
| One embedding space for documents and query | Comparable vectors | Separate models would not be comparable |

## 9. Viva questions with answers

**Q. How does your recommender work?**

A. Average word vectors per document, cosine similarity between the query and all documents, top-k.

**Q. Why cosine similarity and not Euclidean distance?**

A. It compares direction and ignores document length.

**Q. Content-based vs collaborative filtering?**

A. Content-based uses item content; collaborative filtering uses user-item interactions.

**Q. What is the cold-start problem?**

A. New items or users have no interaction data; content-based handles new items.

**Q. Limitation of averaging?**

A. Loses word order and weights all words equally.

**Q. Why are the scores around 0.44?**

A. The tweets are random text, so nothing is truly similar.

**Q. Could you improve it?**

A. TF-IDF-weighted averages, Doc2Vec or a sentence encoder.
