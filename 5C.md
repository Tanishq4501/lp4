## 1. What the PS asks (in plain words)
The same transfer-learning pipeline as 5B, applied to clothing images stored as folders (Fashion-MNIST).

## 2. Dataset
- `fashion mnist`: **12,656 images** in 10 class folders (Ankle-boot, Bag, Coat, Dress, Pullover, Sandal, Shirt, Sneaker, T-shirt-top, Trouser) plus a stray `train` folder that must be skipped.
- Split: 10,125 training and 2,531 validation images (80/20, `seed=42`); images resized to 64x64.

## 3. Notebook walkthrough: every cell, and why

### Cell 0: imports
```python
import os
import numpy as np
import pandas as pd
import tensorflow as tf
import matplotlib.pyplot as plt
from sklearn.metrics import classification_report
```
**Why:** As in 5B, plus `os` to list the class folders.

### Cell 1: aliases
```python
K = tf.keras
L = tf.keras.layers
```
**Why:** `K = tf.keras` and `L = tf.keras.layers` are short names so the model code is easier to read (`K.applications.VGG16`, `L.Dense`).

### Cell 2: dataset
```python
#dataset
root = "fashion mnist"
names = [c for c in sorted(os.listdir(root)) if c != "train"]        # skip the stray "train" folder
kw = dict(image_size=(64,64),batch_size=32,validation_split=0.2,seed=42,class_names=names)
tr = K.utils.image_dataset_from_directory(root,subset="training",**kw)
va = K.utils.image_dataset_from_directory(root,subset="validation",**kw)
#tr = tr.take(60)                  # optional: faster on a slow CPU
```
**Why:** `names` lists the sub-folders in sorted order and **skips the stray `train` folder** (`if c != "train"`); `class_names=names` in `kw` tells Keras to use exactly those 10 folders. `image_size=(64,64)`: these are small 28x28 originals, so 64 is enough and fast. Output: 10,125 training and 2,531 validation images, 10 classes.

**Why not the alternative:** Not letting Keras read every folder: the stray `train` folder would become an 11th class. Not 128x128: the images are tiny, so a larger size only slows training.

### Cell 3: load the base model and add the head
```python
#load base model
base = K.applications.VGG16(include_top=False,input_shape=(64,64,3),weights="vgg16_weights_tf_dim_ordering_tf_kernels_notop.h5")
base.trainable = False
model = K.Sequential([L.Input((64,64,3)), L.Lambda(K.applications.vgg16.preprocess_input), base, L.GlobalAveragePooling2D(),L.Dense(256,activation="relu"), L.Dropout(0.3), L.Dense(len(va.class_names),activation="softmax")])
model.summary()
```
**Why:** Same as 5B with `input_shape=(64,64,3)` and a `Dense(10, softmax)` output (`len(va.class_names)` = 10).

**Why not the alternative:** Not `include_top=True`: that keeps the 1000-class ImageNet classifier. Not `/255` instead of `preprocess_input`: VGG16 was trained with its own scaling (RGB to BGR and subtracting the ImageNet mean), so the base would see unfamiliar values. Not `Flatten` instead of `GlobalAveragePooling2D`: it would create a huge dense layer and over-fit. Not training the base from scratch: it needs far more data and time.

### Cell 4: compile and train the head
```python
#compile
model.compile(optimizer=K.optimizers.Adam(1e-3), loss="sparse_categorical_crossentropy", metrics=["accuracy"])
h1 = model.fit(tr, validation_data=va, epochs=4)
```
**Why:** The base is frozen, so only the new head learns. `Adam(1e-3)` is a normal learning rate for a fresh head; `sparse_categorical_crossentropy` because labels are integers (from the folder order); 4 epochs; `validation_data=va` reports accuracy on the held-out 20 % each epoch.

**Why not the alternative:** Not training everything at once: a fresh random head would send large errors back into the pre-trained layers and damage them.

### Cell 5: evaluate
```python
#evaluate
model.evaluate(va)
X, y = zip(*va.as_numpy_iterator())
X, y = np.concatenate(X), np.concatenate(y) 
pred = model.predict(X).argmax(1)
print(classification_report(y, pred, target_names=va.class_names))
```
**Why:** `model.evaluate(va)` gives accuracy 0.8276 and loss 0.5221 before fine-tuning; the report shows per-class scores: Trouser 0.95, Sandal 0.94, Bag and Sneaker 0.93 (F1), and **Shirt only 0.52**, then Coat 0.74 and T-shirt-top 0.78. Overall accuracy 0.82.

**Why not the alternative:** Not two passes over `va`: it is reshuffled each pass, so images and labels would no longer match (this once gave about 11 % accuracy). `zip(*va.as_numpy_iterator())` reads images and labels together in one pass.

### Cell 6: visualise predictions
```python
#plot
for i in range(8):
    plt.subplot(2, 4, i + 1); plt.imshow(X[i].astype("uint8")); plt.axis("off")
    plt.title(va.class_names[pred[i]], color="g" if pred[i] == y[i] else "r", fontsize=8)
plt.show()
```
**Why:** Shows 8 validation images with the predicted class (green title = correct, red = wrong): a quick visual check of what the model gets right and wrong.

**Why not the alternative:** Not only the report: seeing the errors makes them concrete.

### Cell 7: fine-tune
```python
#fine tune
base.trainable = True
for l in base.layers[:-4]:
    l.trainable = False
model.compile(optimizer=K.optimizers.Adam(1e-5), loss="sparse_categorical_crossentropy", metrics=["accuracy"])
h2 = model.fit(tr, validation_data=va, epochs=2)
print(model.evaluate(va))
```
**Why:** `base.trainable = True` unfreezes VGG16, then `layer.trainable = False` for all but the **last 4 layers**: the late layers hold the most task-specific features, the early layers are generic edges and textures that should stay. **Re-compile** (changing `trainable` only takes effect after compile) with `Adam(1e-5)`, a tiny learning rate so the pre-trained weights are only nudged, then train 2 more epochs on the same data.

**Why not the alternative:** Not learning rate 1e-3: it would destroy the pre-trained weights. Not unfreezing everything: more layers means slower training and a higher risk of over-fitting. Not skipping the re-compile.

### Cell 8: compare both phases
```python
#compare
pd.concat([pd.DataFrame(h1.history), pd.DataFrame(h2.history)], ignore_index=True).plot()
plt.show()
```
**Why:** Concatenates the training histories of the two phases into one plot (loss and accuracy, training and validation): the first 4 points are the head training, the last 2 the fine-tuning, so you can see what fine-tuning changed.

**Why not the alternative:** Not two separate unrelated plots.

## 4. Terminology used in this notebook

| Term | Meaning |
|---|---|
| **Transfer learning** | Reusing a network trained on a big dataset (ImageNet) for a new task. |
| **VGG16** | A 16-weight-layer CNN (13 conv + 3 dense, all 3x3 filters) trained on ImageNet; about 14.7 million parameters in the convolutional part. |
| **ImageNet** | A dataset of about 1.4 million images in 1,000 classes that VGG16 was trained on. |
| **include_top=False** | Drops VGG16's own 1000-class classifier so you can attach your own head and use any input size of at least 32x32. |
| **Freezing (trainable=False)** | The layer's weights are not updated during training. |
| **GlobalAveragePooling2D** | Averages each feature map to one number (512 for VGG16): far fewer parameters than Flatten, less over-fitting. |
| **Fine-tuning** | Unfreezing the last layers of the pre-trained network and training them a little with a very small learning rate. |
| **preprocess_input** | The pixel scaling VGG16 was trained with (RGB to BGR, subtract the ImageNet mean). It replaces /255. |
| **Lambda layer** | Wraps a function (here `preprocess_input`) as a layer so the model applies it itself. |
| **image_dataset_from_directory** | Reads images from one folder per class (the folder name is the label) into a batched tf.data dataset. |
| **validation_split / seed** | Reserves a fraction of the images (20 %) for validation; the same `seed` keeps the training and validation subsets disjoint. |
| **tr.take(60)** | Keeps only the first 60 training batches: a quick test mode for slow CPUs. |
| **Dropout** | Randomly switches off a fraction of units during training only, so the network cannot depend on single units (regularisation). |
| **Adam** | An optimiser that keeps running averages of the gradient and its square, so every weight gets its own adaptive step. Default learning rate 1e-3. |
| **Sparse categorical cross-entropy** | Multi-class loss `-log(probability of the true class)` that takes integer labels (7) instead of one-hot vectors. |
| **Softmax** | Output activation that turns scores into probabilities that sum to 1 (one per class). |
| **Accuracy** | Correct predictions divided by all predictions. Misleading when classes are imbalanced. |
| **Precision** | Of everything flagged positive, the fraction that really is positive: TP / (TP + FP). |
| **Recall** | Of all real positives, the fraction found: TP / (TP + FN). |
| **F1 score** | Harmonic mean of precision and recall: 2PR / (P + R). |
| **Stray folder** | An extra folder (`train`) inside the dataset that is not a class and must be excluded. |

## 5. Theory you must be able to explain

**Same method as 5B.** Frozen VGG16 base, new head, then fine-tuning.

**Why a small image size.** VGG16 accepts any size of at least 32x32. The source images are 28x28 grayscale PNGs, so 64x64 loses nothing and cuts the CPU time.

**Why the result is lower than 5B.** VGG16 was trained on colour photos of natural objects; grey 28x28 clothing images upscaled to 64x64 give weaker features, and Shirt, T-shirt-top, Coat and Pullover look alike.

**Fine-tuning helped more here.** Accuracy rose from 0.828 to 0.861 (+3.3 points), more than in 5B, because the ImageNet features fit this domain less well, so adapting the last layers matters more.

**Compare with 1B.** The plain FNN on the Fashion CSV reached 85.6 %, about the same as VGG16 after fine-tuning (86.1 %): on tiny grayscale images a large pre-trained model brings little extra.

## 6. Why we did this, and why not that

| Decision | Why we did it | Why not the alternative |
|---|---|---|
| Skip the `train` folder | It is not a class | Letting Keras read all folders adds a bogus 11th class |
| `image_size=64` | Small originals, faster training | 128 or 224 adds time without information |
| Frozen base, small head, then fine-tune | Same recipe as 5B | Training from scratch needs more data |
| `1e-5` for fine-tuning | Protect pre-trained weights | `1e-3` damages them |
| Report per-class scores | Shows Shirt is the weak class | Accuracy alone hides it |
